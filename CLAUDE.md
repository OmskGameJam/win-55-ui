## Build & Development Commands

- `npm run dev` — запуск Vite dev-сервера с HMR
- `npm run build` — проверка типов (`vue-tsc -b`) + production-сборка Vite (демо-приложение)
- `npm run build:lib` — library build: Vite (ESM bundle + CSS) + vue-tsc (декларации типов) → `dist/`
- `npm run lint` — ESLint
- `npm run preview` — предпросмотр production-сборки
- `npm run emoji -- <command>` — обслуживание `public/win-55-ui/emoji/emoji-registry.csv` (`add`, `replace`, `remove`, `list`, `sort`, `check`, `classify`, `import`)
- `npm run font -- <command>` - генерация bitmap-шрифтов: одиночные (`strike`, `fallback`, `merge`, `build`, `all`, `check`) и манифест-driven, по `src-font/fonts.json` (`strike-all`, `fallback-all`, `merge-all`, `build-all`, `push-fonts`, `update-register`), см. «Битмап-шрифты» ниже
- `npm run cursors -- <command>` - toolkit для `src-cursors/`: `discover` (пересобрать `manifest.json`) и `sprite [--force]` (рендер в `public/win-55-ui/cursors/`), см. «Курсоры» ниже
- `npm run charedit -- <bdf> [glyph]` - интерактивный TUI-редактор битмапа одного глифа BDF (стрелки - курсор, space - переключить пиксель, `[`/`]` - соседний глиф, `g` - перейти к глифу по имени/кодпоинту/символу, `s` - сохранить, `q`/`Esc` - выход); только битмап - остальные поля (BBX, DWIDTH, свойства) правятся прямо в текстовом `.bdf`. `<bdf>` без абсолютного пути резолвится относительно `src-font/`. При выходе, если была хоть одна сохранённая правка, для каждой грани `fonts.json`, ссылающейся на этот BDF, автоматически перезапускается remerge (если нужен) + build + tofu + push-fonts - `npm run dev` увидит новый TTF сразу (Vite сам делает full-reload на изменения в `public/`)
- `npm run release` — `scripts/release.js`: `build:lib` + `git add -A` + коммит `Publish <version>` (версия берётся из `package.json`, бампается вручную перед запуском)

`paths.config.json` (корень репозитория) — расположение ключевых директорий/файлов (`src-font/`, `public/win-55-ui/font/`, `public/win-55-ui/emoji/`, ...) как JSON, единый источник для обоих build-инструментов: `scripts/font/src/paths.ts` и `scripts/emoji-cli.js` читают его независимо друг от друга (первый компилируется через tsc, второй — обычный JS, запускается как есть, шарить между ними код напрямую не выйдет). Переименование директории — правка одной строки в конфиге, а не grep по двум CLI.

Требуется Node.js 20.19+ или 22.12+ (указан в `.nvmrc`).

## npm-пакет

Устанавливается из git: `npm install github:<owner>/win-55-ui`. `prepare` скрипт автоматически запускает `build:lib`.

Точки входа:
- `win-55-ui-vue` — компоненты и хелперы (ESM)
- `win-55-ui-vue/style.css` — CSS (reset, font-face, классы компонентов)
- `win-55-ui-vue/plugin` — Vite-плагин `win55ui()` для раздачи ассетов из `public/win-55-ui/` (dev: middleware, build: emitFile)

`vite.config.lib.ts` — отдельный конфиг для library build (`publicDir: false`, `transformAssetUrls: false`, `external: ['vue']`).

## Project Overview

Библиотека UI-компонентов в стиле Windows 95, построенная на Vue 3 + TypeScript + Vite. Все компоненты используют `<script setup lang="ts">` (Composition API). `App.vue` — kitchen sink демо всех компонентов.

## Architecture

### Компоненты (`src/components/`)

- **Box** — центральный layout-компонент с 9-patch border-image (CSS `border-image` + PNG из `/public/win-55-ui/`). Тип `BoxType` (`indent`, `indent-dark`, `panel-d-1`, `panel-d-2`, `textarea`, `border-groove`, `white-box`, `notification`) определяет визуальный стиль рамки. Пробрасывает `$attrs` на корневой div.
- **Typography** — обёрточный компонент, применяющий `typographyStyles()`. Принимает props из `TypographySettings` напрямую (kebab-case в шаблонах: `font-color`, `font-shadow-color`). По умолчанию рендерится как `<span style="display: contents">`, с опциональным prop `element` для смены тега. `isBold`/`isItalic`/`fontSize` и `shorthand` резолвятся в реально существующий `@font-face` через registry в `typography.ts` (см. ниже) — запрошенная комбинация, для которой нет битмап-шрифта (например курсив), молча деградирует до ближайшей поддерживаемой, а не рендерится «пустым» системным шрифтом. Опциональный prop `font-name` выбирает семейство шрифта (по умолчанию `"Standard"` — единственное семейство, которое пока реально существует); незнакомое имя деградирует до `Standard` тем же образом.
- **CursorContext** — обёрточный компонент в духе `Typography`, назначающий курсор всему поддереву. По умолчанию тоже `<span style="display: contents">` + prop `element`. Props: `scheme` (тематический набор), `role`, `disabled` (наследуется; выключает кит-курсор для поддерева, рисуется обычный OS-курсор; `<CursorContext :disabled="false">` внутри включает обратно на любой глубине), `mode` (наследуется так же, как `disabled`).

  **Режимы рендера (`mode`)** — `native` (по умолчанию) и `immersive`, наследуется как `disabled`, переключается в поддереве вложенным `<CursorContext mode="...">`.

  `immersive` — исходная схема ниже: `cursor: none` везде, курсор рисует `CursorOverlay` (invert-слой, `mix-blend-mode`, edge-safe у края viewport).

  `native` — реальный CSS `cursor: url()` на спрайт `native.gif` (1:1, не 2×, в отличие от overlay-слоёв), браузер рисует сам. **Инвариант: OS-курсор не показывается нигде, кроме явных opt-out** (`disabled`-контекст, `[data-win55-cursor="off"]`) — иначе всегда либо `default`-роль эффективной схемы, либо контекстная роль (`link` над `<a>`, `text` над `textarea`/`contenteditable`/текстовыми `input`). Три наследуемых по DOM свойства (`helpers/cursorContext.ts`), которые проставляет `CursorContext`/`v-cursor`/`root` и рисуют правила `index.css`:
    - `--win55-cursor-native` — база поддерева (`url(...) x y, kw`, либо `auto` в `disabled`-зоне), рисуется глобальным `* { cursor: var(--win55-cursor-native, none) !important }`. Это `default`-роль, либо закреплённая `role`/busy/progress.
    - `--win55-cursor-native-link` / `--win55-cursor-native-text` — резолвнутые `link`/`text` роли схемы, рисуются `:where(a[href]) {}` / `:where(textarea, [contenteditable], input[...]) {}` (нулевая специфичность через `:where()` — бьют только `* {}` по порядку, проигрывают любому реальному селектору и inline `!important` от `v-cursor`).

    `resolveCursorCss()` (`helpers/cursors.ts`) мэпит `scheme`+`role` -> `url("…/native.gif") x y, <keyword>` (x/y — сырой хотспот `manifest.json`, без множителя; `native.gif` есть у каждого курсора, флага в манифесте нет). `native.gif` печёт `sprite`: normal- и invert-слои слиты в один плоский битмап без blend (`native` рисует голым CSS `url()`) — снизу вверх: белая drop-shadow invert-пикселей со сдвигом 1px вправо-вниз (background-independent замена screen-invert), затем сами invert-пиксели сплошным чёрным, затем реальные пиксели normal-слоя. `CursorOverlay` `native.gif` не грузит. Для always-on путей (база + `link`/`text` деривация) — `resolveCursorCssThemed()`: нерезолвнутая роль откатывается на `default`-роль схемы, а не на голый CSS-keyword. Явно закреплённая через `role`/`v-cursor` нерезолвнутая роль остаётся голым keyword (осознанный запрос).

    Каждый `CursorContext`, меняющий тему поддерева (`scheme`, `role`, busy/progress, `disabled`, явный `:disabled="false"`), перепроставляет все три свойства — вложение перетемизирует и деривацию. Пустой вложенный `<CursorContext>` прозрачен (ничего не ставит, наследует предка — как в immersive). Закреплённая `role` «схлопывает» поддерево: `link`/`text` = базовому значению (весь subtree — один курсор). `disabled` в `native` — как в immersive: `--win55-cursor-native: auto` на всё поддерево (OS-курсор), вложенный `:disabled="false"` возвращает тему. `root` ставит базу на `<html>` и всегда монтирует `CursorOverlay` (в `native` тот инертен — прячется, когда `--win55-cursor-native` под указателем не `none`).

    Не покрыто `native`-деривацией (пока, «следующий шаг»): авторский инлайновый `cursor: move`/`grab`/`col-resize` на произвольном элементе (глобальный `!important` перебивает его на `default`); ресайз-зоны `Window`. `wouldBeCursorRole` (чтение инлайнового `cursor` в JS) работает только в `immersive`. Настоящий screen-invert — тоже только `immersive`; в `native` invert выглядит как плоский чёрный силуэт с белой drop-shadow. Анимация `.ani` в `native.gif` сохраняется (многокадровый GIF).

  Кит **никогда не рисует нативный курсор** (в режиме `immersive`): `index.css` глушит его глобально (`* { cursor: var(--win55-cursor-native, none) !important }` — inherited `none` не победил бы собственный `cursor` ссылок/полей ввода/ресайзеров, и OS-курсор рисовался бы поверх нарисованного; `--win55-cursor-native` наследуется: `disabled`-контекст ставит его в `auto` (не `revert` - CSS-wide keyword в кастомном свойстве не хранится; в `disabled`-зоне OS-курсор это стрелка + I-beam над текстом, но не pointer над ссылками), вложенный включённый - обратно в `none`), а рисует курсор единственный `CursorOverlay` под `root` (см. ниже), по трём наследуемым по DOM (точно как `cursor`, но браузер их не рисует) кастомным свойствам из `helpers/cursorContext.ts`:
  - **`CURSOR_TOKEN_PROPERTY` (`--win55-cursor`)** — уже резолвнутый `cursorId`. Проставляется только там, где роль *закреплена*: prop `role`, `v-cursor`, или активные busy/progress. `resolveCursor()` (`helpers/cursors.ts`, асинхронный fetch+кэш `manifest.json`/`scheme.json` из `public/win-55-ui/cursors/`, публикуются `npm run cursors -- sprite`) мэпит `scheme`+`role` -> `cursorId`; если у схемы нет такой роли (не каждый набор содержит `help`/`handwriting`) — откат на ту же роль в `windows-default`.
  - **`CURSOR_SCHEME_PROPERTY` (`--win55-scheme`)** — эффективная схема. `root` ставит её на `<html>`, `<CursorContext scheme=...>` переопределяет для своего поддерева.
  - **`CURSOR_NATIVE_PROPERTY` (`--win55-cursor-native`)** — в `immersive`: `auto` там, где кит-курсор выключен (см. `disabled` выше), `none` где вложенный контекст включил обратно. В `native` — готовое `url(...) x y, kw` (см. блок про режимы выше). Читают `index.css` и `CursorOverlay` (прячет overlay, когда значение не `none`).

  Без закреплённой роли (`<CursorContext>` без `role`, `<CursorContext scheme="dinosaur">`, голый контент под `root`) токена нет, и `CursorOverlay` **выводит роль из того, какой курсор браузер нарисовал бы сам** (`wouldBeCursorRole`): т.к. `getComputedStyle().cursor` теперь всегда `none`, смотрит ближайший инлайновый `cursor` (`cursor: move` -> `move`), затем маленькую UA-модель (`a[href]` -> `link`, текстовые `<input>`/`textarea`/`contenteditable` -> `text`, `:disabled` -> `not-allowed`), иначе `default`; keyword -> роль по таблице `NATIVE_ROLE`. Резолвит в схеме из `--win55-scheme`, результат кэшируется. Так существующая разметка (ссылки, поля ввода, любой авторский инлайновый `cursor:`) получает тематические курсоры без единого `v-cursor`. Токен, если есть, всегда бьёт вывод. `data-win55-cursor="off"` на элементе/предке — escape hatch для не-Vue разметки (игровой `<canvas>` и т.п.): плоский `cursor: revert !important` (полный per-element UA-курсор, в отличие от `disabled`-`auto`), но без вложенного re-enable; overlay не рисует. Prop `root` — вместо инлайн-стиля на собственной обёртке `cursor: none` + токен + схема проставляются на `document.documentElement` (`<html>`, не `<body>`) напрямую, монтируется `CursorOverlay`, и контекст регистрируется модульным singleton'ом (`setRootCursorContext`, `helpers/cursorContext.ts`). Доп. prop `disable-all` (только на `root`) — жёстко выключает кит-курсор везде, перебивая любой вложенный `:disabled="false"` (через модульный флаг `setGlobalCursorDisabled`). Нужен ровно для одного самого верхнего `CursorContext`, оборачивающего всё приложение: CSS-наследование идёт по настоящему DOM, а не по логическому дереву компонентов Vue, так что голый фон страницы и любой `<Teleport to="body">`-контент (меню `BaseDropdown`/`MenuDropdown`, `Window`, ...) в реальном DOM оказываются не потомками обёртки, а её соседями под `<body>` — наследование туда не дотягивается, только явный проставленный на корне стиль покрывает вообще всё. `<html>`, а не `<body>` — у `<body>` после Meyer-ресета (обнуляет margin, но не заставляет `height: 100%`) собственный box ровно по высоте/ширине контента, так что он не гарантированно предок каждого наводимого пикселя, а `<html>` как настоящий корень вьюпорта — всегда.

  Singleton нужен для `v-cursor` внутри `<Teleport>`: директива ищет свой `CursorContext` обходом настоящего DOM (`findNearestCursorContext`), а телепортнутый контент — DOM-сосед корня приложения, не потомок обёртки `root`, так что обход не находит ничего и падает на зарегистрированный `root`-контекст (иначе резолв шёл бы по `windows-default` мимо активной схемы). `<CursorContext>`-*компоненты* этой проблемы не имеют — они через `inject()`, а он идёт по дереву компонентов сквозь `<Teleport>`.

  **`CursorOverlay`** (`src/components/CursorOverlay.vue`, не экспортируется — внутренняя деталь `CursorContext`) — DOM-элемент, который и есть курсор (CSS `cursor` везде `none`). Существует потому, что `cursor: url()` не рисуется у края viewport (см. ниже) и не умеет invert/blend-слой; `position: fixed` элемент свободен от обоих ограничений. Что показывать — берёт из `getComputedStyle(elementUnderPointer)`: `--win55-cursor` (готовый `cursorId`) если закреплён, иначе `wouldBeCursorRole` (инлайновый `cursor` + UA-модель, см. выше) резолвит роль в схеме из `--win55-scheme`, вывод кэшируется. `hasNormal`/`hasInvert` и хотспот (x2) — из `manifest.json` по `cursorId`. Позиция пишется прямо из pointer-события (`pointermove`, плюс `pointerrawupdate` где есть) в `style.transform` — compositor-only, без чтения layout и без rAF-хопа. Identity резолвится не пофреймно, а по событию: `pointerover` (пересечения границ элементов) плюс редкий interval-sweep (~120ms) для случаев «указатель стоит, а курсор под ним сменился» (busy/progress, сдвиг элемента); `visibilitychange` глушит sweep в фоне. Подробный разбор задержки — в док-комментарии `CursorOverlay.vue`. `hasNormal`/`hasInvert` для `cursorId` — поле из `manifest.json` (см. «Курсоры» ниже, публикуется, а не досчитывается): `<img>` показывается только если слой реально существует, без попыток словить 404. Обе `<img>` (invert снизу с `mix-blend-mode: difference`, normal сверху) — два соседних `position: fixed` элемента (`z-index: 2147483647`, `pointer-events: none`), телепортированных прямо в `<body>` **без обёртки**: любой трансформированный предок изолировал бы blend-группу invert-слоя от страницы, которую тот инвертирует, поэтому `style.transform` для позиции пишется на каждый `<img>` по отдельности, а не на общий контейнер. Позиция округляется до 2px-сетки (тот же грид, что у остальных пиксель-арт ассетов кита).

  **Ограничение `cursor: url()` у края viewport** (причина, по которой курсор рисует `CursorOverlay`, а не CSS): у самого края (сверху/слева ~20px, снизу/справа ~44px при спрайте 64x64 и hotspot ~(20,20)) браузер не может отрисовать битмап так, чтобы часть вылезала за viewport, и откатывается на fallback вместо частичной отрисовки — так во всех браузерах. У настоящего Windows то же самое для нативных курсоров у края физического экрана, так что это не потеря аутентичности, а она и есть. `position: fixed` элемент (`CursorOverlay`) этому не подвержен — под `root` (единственная поддерживаемая конфигурация) мёртвой зоны нет.

  Каждый из props, если не задан явно, наследуется от ближайшего предка-`CursorContext` (а не от жёсткого дефолта) — вложенность полностью прозрачна: `<CursorContext scheme="dinosaur"><CursorContext role="not-allowed">` резолвит `not-allowed` именно в `dinosaur`, не трогая `scheme`. Жёсткие дефолты (`"windows-default"`/`"default"`) применяются только на самом верхнем уровне, где предка ещё нет. Реализовано через `provide()`/`inject()` (`helpers/cursorContext.ts`, ключ `CURSOR_CONTEXT_KEY`): контекст отдаёт вложенным потомкам свои эффективные (уже с учётом своего наследования) `scheme`/`role` computed-рефами, плюс колбэк `resolveRole(role)`, резолвящий роль относительно текущей эффективной схемы. Вложенный `CursorContext` берёт `useCursorContext()` предка и для каждого не заданного явно prop использует именно эти эффективные значения. Для обычного компонента — тот же `useCursorContext()` (обычный `inject()`). Для директивы `v-cursor` (см. ниже) обычный `inject()` не работает: в `@vue/runtime-core` DOM-патчинг директив идёт уже после `unsetCurrentInstance()`, так что `inject()`, вызванный прямо из хука директивы, не видит нужный instance.

  `CursorContextApi` (тот же provide/inject-объект) также несёт `addBusy(promise)`/`addProgress(promise)` — пока переданный `Promise` не settled (resolve или reject — снимается через `finally`), у этого контекста `hasBusy`/`hasProgress` (computed-рефы) становятся `true`, и роль `default` (только она — `not-allowed`/`ns-resize`/явно указанная роль никогда не подменяются) резолвится не в свой обычный курсор, а в `wait` (busy, копия Windows `IDC_WAIT` — сплошные песочные часы, приоритет выше) либо `progress` (копия `IDC_APPSTARTING` — стрелка+часы). И busy, и progress — независимые `Set<Promise>` (`reactive`, не счётчик — повторное добавление того же промиса не задваивает, повторное снятие безопасно), логика подмены роли — в `roleForState()`. Состояние распространяется только вниз по вложенности (как `scheme`/`role`): `hasBusy`/`hasProgress` контекста — это его собственные промисы ИЛИ `hasBusy`/`hasProgress` родителя, никогда наоборот — потомок физически не может повлиять на предка через `provide`/`inject`, так что `addBusy` на одном контексте не задевает соседние поддеревья. И `CursorContext`, резолвящий свой собственный курсор, и `v-cursor` вызывают один и тот же `resolveRole()` — оба живут через постоянный `watchEffect` (не разовый resolve при монтировании), так что уже отрендеренный курсор переключается на `wait`/`progress` вживую, без размонтирования. `CursorContext` также прокидывает `addBusy`/`addProgress`/`resolveRole` через `defineExpose` — можно дёрнуть их через template ref, а не только через `useCursorContext()` из потомка. `useCursorContext()` — обычный `inject()`, поэтому достаёт ближайший контекст с любой глубины вложенности без ref-цепочки; `addBusy`/`addProgress`, однажды полученные так, — обычные замыкания над `reactive`-стейтом, не завязанные на «текущий инстанс» Vue, так что их можно свободно передавать в чужую (в том числе полностью не-Vue) логику и звать оттуда, а не только сразу на месте — пример в `CursorBusyDemoButton.vue` (`helpers/simulateWork.ts` — без единого Vue-импорта).
- **BaseInput** — использует `contentEditable` div (обёрнут в Box) вместо HTML input. Поддерживает maxLength, paste (plain text only), блокировку Enter/Tab, Discord-style `:shortcode:` emoji-автокомплит (popup через `Balloon`, данные из `helpers/shortcodes.ts`). Emit `change` с новым значением. Опциональный prop `showEmojiButton` добавляет кнопку внутри поля (видна при фокусе или когда пикер таргетит именно этот инпут), открывающую глобальный `EmojiPickerWindow` и вставляющую выбранный эмодзи в последнюю известную позицию каретки.
- **EmojiPickerWindow** — full-size emoji picker: глобальный singleton (один `Window` на всё приложение, монтируется один раз, например в `App.vue`), состояние — `helpers/emojiPickerStore.ts` (open/position/size только в памяти, сбрасываются при перезагрузке; активный `BaseInput`-таргет через `shallowRef`, а не `ref`, чтобы не терять identity объекта под reactive Proxy). Категории эмодзи — `helpers/emojiCategories.ts` (`emoji-by-category.json`). Закрывается по клику вне себя. Иконка тайтлбара перевыбирается при каждом открытии.
- **RichText / RichTextNode** — рендерит ограниченный BBCode ( `[b] [i] [u] [s]/[strike] [color=] [size=] [url]/[url=] [br]` ) плюс `:shortcode:` эмодзи из **собственного текстового содержимого** slot'а (не через text-prop) в дерево `Typography`/span/`<a>`. Парсер — `helpers/richText.ts`, лениентный к неизвестным/незакрытым тегам (передаются как литеральный текст). `[url]` рендерится только при `allow-links` (по умолчанию `false`); без него — тег молча «не работает», рендерится только текст внутри. Ссылки всегда `target="_blank"`. `RichTextNode` — рекурсивный внутренний компонент, не экспортируется отдельно.
- **BaseDropdown / MenuDropdown** — dropdown-система с `<Teleport to="body">` для предотвращения clipping. Автоматически переворачивается вверх при overflow. Используют named slots: `#trigger` и `#items`.
- **Checkbox, RadioButton** — скрытый нативный input + кастомная иконка (img). Emit `change`. RadioButton сравнивает `target` с `value` для определения checked-состояния. Курсор — `v-cursor="disabled ? 'not-allowed' : 'link'"` на контейнере (не хардкод `cursor: pointer`/`not-allowed` инлайн-стилем: это перебивало бы наследование от `CursorContext`, т.к. явно заданный на элементе `cursor` всегда сильнее унаследованного, независимо от specificity).
- **Button** — кастомная обработка mousedown/mouseup (глобальный listener на window). Меняет BoxType на `indent` при нажатии. Emit `click` только если мышь внутри при отпускании. Курсор — та же `v-cursor="isDisabled ? 'not-allowed' : 'default'"` на `Box`, по той же причине.
- **Window** — перемещаемое/ресайзабельное окно с абсолютным позиционированием. Использует `defineModel` для `x`, `y`, `width`, `height`. Поддерживает направленный resize (по краям окна, 6px зона) и drag строго за titlebar-полосу (исключая иконку и кнопки тайтлбара — клик по ним не должен таскать окно). Во время drag/resize на `document.body` временно ставится `user-select: none`, чтобы жест не выделял текст. Props `resizable`, `resizableHorizontally`, `resizableVertically`.
- **Balloon** — всплывающее уведомление с «хвостиком» (треугольная стрелка). Позиционирование: `side` (top/bottom/left/right) + `bias` (left/right/up/down) для смещения. Использует `defineModel` для `shown`. Контент через `#content` слот или prop `text`.
- **Tooltip** — тултип, следующий за курсором. Появляется с задержкой 400ms при наведении. Props: `text`, `offsetX`, `offsetY`. Оборачивает контент через default slot.
- **HDivider** — горизонтальный разделитель (Box type `border-groove` с нулевой высотой).
- **NamedPanel** — Box с `border-groove` и плавающим лейблом сверху (абсолютно позиционированный `<div class="label">`). Props: `label`, `backgroundColorHint` (по умолчанию `#CBCBCB`). Контент через default slot.
- **Titlebar** — рендерит Bayer-dithered градиент на canvas с ResizeObserver для адаптивной перерисовки.
- **Custom Cursor directive** (`src/directives/cursor.ts`) — `v-cursor="role"` меняет курсор одного элемента (или, через штатный fallthrough директив на компонентах, корневого элемента компонента) на другую роль той же активной схемы, что и у ближайшего предка `CursorContext`. `role` (и prop `role` у `CursorContext`) типизирован как `CursorRole` — открытый union (`'link' | 'text' | 'not-allowed' | ... | (string & {})`, `helpers/cursorContext.ts`): известные роли автокомплитятся в IDE, незнакомая всё равно валидна (резолв с откатом на `windows-default`). — например `<Button v-cursor="'not-allowed'">` внутри `<CursorContext scheme="dinosaur">` берёт `not-allowed` из `dinosaur`, не трогая `scheme`. Как и `CursorContext`, ставит `cursor: none` + токен `--win55-cursor` — нативный курсор не рисуется никогда. Нет предка-`CursorContext` в DOM-обходе — берётся зарегистрированный `root`-контекст (см. выше; так `v-cursor` внутри `<Teleport>`-контента резолвится по активной схеме, а не мимо неё); `windows-default` — только если и `root`-контекста нет вообще.

  Достаёт `CursorContextApi` не через `inject()` (не работает внутри хука директивы, см. выше) и не через `binding.instance._.provides` (первая версия этого директива делала именно так — рабочий вариант для `v-cursor`, написанного внутри шаблона самого `Button`/`Checkbox`/`RadioButton`, но систематически ломающийся, стоит написать `<CursorContext><div v-cursor="...">` в ОДНОМ шаблоне: slot-контент компилируется через `_withCtx`, который намеренно привязывает создание vnode — а значит и то, что видит `withDirectives()` как `binding.instance` — к компоненту, написавшему slot, а не к тому, что его отрендерил; реальные `provide()`/`inject()` эту ловушку не имеют, потому что резолвятся по фактическому mount-time родителю, а не через `_withCtx`), а через настоящий обход DOM — `findNearestCursorContext()`/`markCursorContextElement()` (`helpers/cursorContext.ts`): каждый `CursorContext` кладёт свой `CursorContextApi` прямо на собственный отрендеренный DOM-элемент (обычное свойство объекта, не Vue-механизм) в `onMounted`, а директива поднимается по настоящим `.parentElement` до ближайшего помеченного. Сам поиск отложен до `nextTick()` — `onMounted` предка-`CursorContext` штатно срабатывает уже ПОСЛЕ `mounted` всех потомков (в т.ч. этой директивы), так что синхронный поиск прямо из `mounted` систематически не находил бы ничего ни при каком из двух подходов; `nextTick()` гарантированно отрабатывает уже после того, как весь начальный рендер (и все `mounted`-хуки в нём) осел.
- **Custom Emoji directive** (`src/directives/emoji.ts`) — Vue-директива для замены emoji в текстовых нодах на GIF-изображения из `/win-55-ui/emoji/`. Регистрируется как `app.directive('emoji', emojiDirective)` и используется как `v-emoji`, обычно один раз на верхнем компоненте приложения. Внутри есть `MutationObserver`, поэтому динамический текст и `BaseInput` тоже обрабатываются. Emoji wrapper — один non-editable inline-atom с оригинальным Unicode emoji в `data-win55-emoji` для копирования/сериализации; GIF всегда следует 2x масштабу UI kit: 15px ассет → 30px на экране. Тот же визуальный конвеншн (`.win55-emoji` / `.win55-emoji-image`) переиспользуется в `RichTextNode` и в emoji picker.

### Helpers (`src/helpers/`)

- **typography.ts** - `typographyStyles()` возвращает `CSSProperties` (из Vue). Маппит fontName+размер+начертание на custom @font-face. Физическое имя TTF-файла и CSS `font-family` всегда совпадают и следуют схеме `{fontName}-{style}-{size}` (например `Standard-Regular-12`, файл `public/win-55-ui/font/Standard-Regular-12.ttf`) - `"Standard"` это собственное имя шрифта UI-кита, не привязанное к тому, какой конкретно исходный векторный шрифт (сейчас Liberation Sans) использовался для генерации битмапа. Поддерживает shorthand: `"Bold12"` (только style+size, без fontName). Импортирует `SUPPORTED_FACES` из `generatedFonts.ts` (auto-generated, не редактировать руками - см. «Битмап-шрифты» ниже) и через fallback-цепочку (`BoldItalic->Bold->Italic->Regular` и т.д.) деградирует любую запрошенную комбинацию fontName/стиля/размера до ближайшей реально поддерживаемой (незнакомый `fontName` - до `Standard`).
- **richText.ts** — `parseRichText()`, парсер ограниченного BBCode + `:shortcode:` эмодзи в дерево `RichNode` для `RichText`/`RichTextNode`.
- **shortcodes.ts** — `loadShortcodeIndex()` (кэширующий fetch `emoji-categories.json`), `searchShortcodes()` (prefix-поиск для автокомплита в `BaseInput`), `resolveShortcode()` (точное совпадение `:name:`).
- **emojiCategories.ts** — `loadEmojiCategories()`, кэширующий loader `emoji-by-category.json` (эмодзи, сгруппированные по категориям для `EmojiPickerWindow`). Оба JSON генерируются CLI-командой `npm run emoji -- classify`, ручное редактирование не требуется.
- **emojiPickerStore.ts** — модульный (не Pinia) reactive singleton для глобального emoji picker: `pickerOpen`, `pickerPosition` (in-memory), `activeTarget` (`shallowRef`, не `ref` — иначе Vue задиповает объект-таргет в Proxy и `===`-сравнение сломается), `openPicker`/`closePicker`/`insertEmoji`, `pickNextButtonIcon` (циклическая, не случайная, общая для всех `BaseInput`).
- **emojiDom.ts** — DOM-хелперы для работы с contentEditable-содержимым `BaseInput`: `getTextWithCustomEmoji`, `getSelectionOffset`/`restoreSelectionOffset` (кодируют/восстанавливают позицию каретки в grapheme-офсетах, устойчивы к emoji-обёрткам).
- **caretPosition.ts** — `getCaretClientRect()`, экранные координаты каретки (для позиционирования popup автокомплита).
- **graphemes.ts** — `graphemeLength`/`sliceGraphemes`, Unicode-grapheme-aware операции над строками (эмодзи как «один символ»).
- **color.ts** — `parseHexPalette`/`findNearestColor`, используется в emoji-директиве для quantization канвас-фолбэка нераспознанных unicode emoji.
- **bayerMatrix.ts** — 8x8 Bayer dithering для canvas-градиентов.
- **useSineWave.ts** — composable (`ref` + `requestAnimationFrame`) для анимированных sine/cosine значений с configurable FPS. Нормализует высоты для постоянной суммы.
- **imgErrors.ts** — `registerGlobalImageErrorHandler` — глобальный fallback на `broken-image.png` при ошибках загрузки изображений (capture phase listener).
- **emoji.ts** — runtime emoji registry loader. Загружает `public/win-55-ui/emoji/emoji-registry.csv` в браузере через `fetch`, читает его как простой `emoji,code` key-value файл и кэширует результат. Не генерировать TS-реестр; для обновления CSV использовать `npm run emoji -- add/replace/remove/...`.
- **browser.ts** — `isFirefox()` (UA sniff). Используется в `emoji.ts`-директиве и `BaseInput` для Firefox-only костылей вокруг размещения каретки рядом с custom-emoji атомами (лишние пустые текстовые ноды, ручная обработка стрелок) — в Chrome эти костыли не нужны и мешают нативному OS emoji-панели.

## Conventions

### Vue-паттерн компонентов

- Все компоненты используют `<script setup lang="ts">` с `defineProps`/`withDefaults`/`defineEmits`.
- Кастомизация внешнего вида через props `extraStyles` (`CSSProperties`) и `extraClass` (`string`).
- Компоненты, которым нужен DOM-доступ извне, используют `defineExpose`.
- Состояние управляется через `v-model` (`defineModel`). Компоненты форм (BaseInput, Checkbox, RadioButton) используют `modelValue`/`update:modelValue`. Window использует именованные модели (`x`, `y`, `width`, `height`). Balloon — `shown`.

### Стилизация

Plain CSS (`index.css`, `scrollbar.css`) + inline `CSSProperties`. Без CSS-модулей, препроцессоров или CSS-in-JS. Все изображения используют `image-rendering: pixelated` для пиксельной эстетики.

### Ассеты

Все UI-ассеты (PNG-рамки, шрифты, иконки) в `/public/win-55-ui/`.

Emoji GIF-ассеты и runtime registry лежат в `/public/win-55-ui/emoji/`. CSV должен публиковаться вместе с ассетами и читаться на runtime. `npm run emoji -- classify` дополнительно генерирует `emoji-categories.json` (плоский, для автокомплита/шорткодов) и `emoji-by-category.json` (сгруппированный по категориям, для `EmojiPickerWindow`) — оба публикуются рядом с CSV и не редактируются вручную.

`/public/win-55-ui/x-emoji/` — staging-папка для нестандартных emoji-гифок, названных по алиасу (например `rofl.gif`), а не по символу. `npm run emoji -- import` резолвит алиас → unicode-эмодзи через github/iamcal/joypixels shortcode-пресеты `emojibase-data`, копирует гифку в `emoji/` под новым кодом из зарезервированного диапазона `C00`–`FFF` (отдельного от секвенциального `000`–`BA1` основного реестра) и сразу перезапускает `classify`.

`scrollbar.css` — кастомные `::-webkit-scrollbar-*`. Кнопки-стрелки обязательно квалифицированы `:start`/`:end` (без этого WebKit рисует обе кнопки на обоих концах). Хелпер-классы для конфигурации стрелок: `.scrollbar-arrows-none`, `.scrollbar-arrows-normal`, `.scrollbar-arrows-start`, `.scrollbar-arrows-end`.

### Битмап-шрифты (`scripts/font/`, `src-font/`)

`npm run font -- <command>` - TypeScript-инструмент (компилируется через собственный `scripts/font/tsconfig.json` перед запуском, `npm run font:build`) для генерации pixel-perfect bitmap-шрифтов, заменяющий ручной процесс FontForge + AutoTrace. Ни FontForge, ни AutoTrace, ни Python не нужны - но **растеризация Windows-only**: `strike`/`fallback` (`rasterize.ts`) рисуют через DirectWrite (`directwrite.ts`), системный `dwrite.dll`, вызываемый напрямую через FFI (`koffi`, ручной COM vtable dispatch) - без нативных аддонов и без build-тулчейна, но и без переносимости на другие ОС. Обратная векторизация (`build`) - через собственный контурный трейсер (`contours.ts`, 4-connected boundary tracing) + `svg2ttf` (не `opentype.js` - см. `FONTS.md`). Почему именно DirectWrite и как устроен vtable dispatch - там же.

Одиночный пайплайн (по одному шрифту за раз): `strike` (растеризация исходного TTF в `.bdf` для конкретного pixel size; опционально авто-кернинг, см. `FONTS.md`) -> опционально `fallback` + `merge` (добор недостающих глифов из другого, более полного TTF) -> ручной просмотр/правка `.bdf` (простой текстовый формат - редактировать можно прямо в нём, отдельного preview/PNG-шага нет) -> `build` (BDF -> outline TTF; `unitsPerEm = pixelSize * 100`, поэтому каждая пиксельная граница кратна 100 юнитам "по построению" - не нужно вручную сверять em-size, как в старом FontForge-процессе; мягкие находки самопроверки пишутся в `<out>.report.json`, не блокируя сборку) -> `tofu` (строит из `?`-глифа этого же BDF однострочный fallback-шрифт `{name}-TofuMaker.ttf`, см. ниже). `strike`/`fallback`/`all` отказываются перезаписывать существующий `.bdf` без `--force`, т.к. он может быть вручную отредактирован. `npm run font -- check <bdf>` - быстрая структурная проверка (битые/дублирующиеся глифы) без полной сборки.

Манифест-driven пайплайн (по всем шрифтам сразу, источник истины - `src-font/fonts.json`): `strike-all`/`fallback-all`/`merge-all`/`build-all`/`tofu-all` повторяют те же шаги для каждой записи манифеста, у которой ещё нет соответствующего выходного файла - существующий файл не перезаписывается, а пропускается с предупреждением (можно свободно перегенерировать только недостающие части набора). `push-fonts` копирует готовые TTF (основной + TofuMaker) из `src-font/` в `public/win-55-ui/font/` (всегда перезаписывает - это финальный шаг публикации). `update-register` полностью перегенерирует `src/helpers/generatedFonts.ts` (`SUPPORTED_FACES`) и `src/generated-fonts.css` (по два `@font-face`-блока на грань: основной шрифт + его TofuMaker) из `fonts.json` - оба файла помечены как auto-generated, руками не редактируются. `full-pipeline-all` прогоняет все семь шагов подряд с progress bar по стадиям. Полная схема `fonts.json`, авто-кернинг (`--generate-kerning` и связанные флаги `strike`/`fallback`) и TofuMaker - см. `FONTS.md`.

**TofuMaker**: каждая грань получает шрифт-компаньон `{fontName}-{style}-{size}-TofuMaker`, состоящий из ровно одного глифа (символ `?` из BDF этой самой грани), сопоставленного через cmap format 13 буквально каждому валидному Unicode-кодпоинту разом, без дублирования контура. Прописан в CSS font-family стеке в `typography.ts` сразу после основного шрифта, перед `Arial, sans` - гарантирует, что для любого символа, для которого нет своего пиксельного глифа, браузер отрисует наш собственный пиксельный `?`, а не соскочит на гладкий системный шрифт.

`src-font/` - staging-директория пайплайна: `liberation_sans/`, `noto_sans_jp/` (исходные векторные TTF, не редактируются), `fonts.json` (манифест), плюс сгенерированные `.bdf`/`.ttf` по размеру/начертанию - все текущие `.bdf`/`.ttf` в этой папке порождены самим пайплайном (`full-pipeline-all`), не унаследованы из старого ручного FontForge-процесса.

### Курсоры (`scripts/cursors/`, `src-cursors/`)

`src-cursors/` - staging-директория (та же роль, что `src-font/` для шрифтов): плоский набор файлов `<scheme-slug>-<role>.<ext>` (`default.cur`/`crosshair.cur`/`text.cur`/`ns-resize.cur`/... на роль; анимированные роли - `.ani`), по одному физическому файлу на уникальный курсор - байт-идентичные дубликаты между схемами хранятся один раз (см. `scheme.json` ниже). Источник материала - 19 курсорных наборов: 18 скопированы бит-в-бит из `C:\Windows\Cursors` по официальному реестровому списку схем (`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Control Panel\Cursors\Schemes`), один (`windows-default`) - разовый живой захват активных курсоров этой машины (кастомная Win95-сборка держит их не файлами, а патченными ресурсами `user32.dll`, поэтому обычное копирование не сработало бы) через нативный Win32 `LoadImage`/`GetIconInfo`/`GetDIBits` по `OCR_*` ID, с ручной пересборкой в валидный `.cur`. Скрипта захвата в репозитории нет и не будет - `src-cursors/` не перегенерируется из живой ОС, это замороженный вход для тулкита.

`npm run cursors -- <command>` - TS-инструмент, той же формы, что `scripts/font/` (собственный `scripts/cursors/tsconfig.json`, компилируется через `npm run cursors:build` перед запуском). Две команды: `discover` (метаданные) и `sprite` (рендер в веб-ассеты).

Манифест и схемы намеренно разнесены по разным файлам с противоположной ответственностью - манифест ничего не знает о схемах, схемы не хранят физических свойств файла:

**`src-cursors/manifest.json`** - `{ [cursorId]: CursorEntry }`, чисто физические свойства файла, без единого намёка на то, какая схема/роль на него ссылается; по одной записи на физический файл (не на пару схема/роль), `cursorId` = имя файла без расширения, например `3d-bronze-crosshair`. Полностью перегенерируется `discover`, руками не редактируется, кроме `sourceFile`/`reconstructed`:
- `file` - имя файла в `src-cursors/`.
- `sourceFile?` (оригинальное имя в `C:\Windows\Cursors`, либо `live:OCR_<id>` для живого захвата - провенанс, не выводится из самого файла), `reconstructed?` (см. ниже) - сохраняются между запусками, не пересчитываются.
- `animated`, `width`/`height`/`hotspotX`/`hotspotY`, `bitcounts` (XOR-глубины среди кадров, обычно одна), `frameCount`, `usesInvert`/`invertFrames` (см. ниже), `suspiciousInvertFrames` (инверт-пиксели с XOR-цветом отличным от чистого белого - см. ниже) - выводятся заново из самого файла при каждом запуске, старому манифесту не доверяют (кроме `reconstructed`-записей, см. ниже).

**`src-cursors/scheme.json`** - `{ [schemeSlug]: { displayName, roles: { [role]: cursorId } } }`, реальная принадлежность курсоров схемам живёт целиком здесь. `roles` - мэппинг роль -> `cursorId` (несколько схем могут указывать на один и тот же `cursorId` - байт-идентичный дубликат, см. ниже); `discover` не может вывести это из простого сканирования `src-cursors/` (после дедупликации проигравшие копии на диске отсутствуют), поэтому сохраняет `roles` из предыдущего `scheme.json` как есть, только проверяя, что каждый `cursorId` всё ещё существует в манифесте - если файл удалили/переименовали не поправив `scheme.json`, такая роль вычёркивается и подсвечивается в выводе `discover` как требующая ручной правки. `displayName` - человекочитаемое имя схемы (из реестрового скрейпа), тоже сохраняется между запусками; для схемы без предыдущей записи - грубый тайтлкейс от slug.

`usesInvert`/`invertFrames` - обнаружение классического AND/XOR screen-invert трюка (пиксель с AND=1 и ненулевым XOR инвертирует то, что под курсором, а не рисует сплошной цвет) в каждом курсоре/кадре - его нельзя честно передать плоским CSS `cursor`/PNG, нужен отдельный слой с `mix-blend-mode: difference` (см. `sprite` ниже). `suspiciousInvertFrames` - инверт-пиксель с XOR-цветом не белым (а не чёрным/белым/прозрачным) - `mix-blend-mode: difference` воспроизводит побитовый XOR только на крайних значениях 0/255, так что такой пиксель либо реальный экзотический курсор (ни один из текущих 193 не является таким - проверено поштучно), либо мусор от кривой конвертации; не считать намерением автоматически, смотреть глазами. `reconstructed: true` помечает файлы, пересобранные из живого `HCURSOR` (все 14 курсоров `windows-default`) - у них AND/XOR-структура уже сплющена в 32bpp цвет+альфа при захвате, так что `usesInvert`/`bitcounts` для них `discover` не выводит заново из файла, а сохраняет как есть из предыдущего манифеста (единственное исключение из принципа «бинарные поля всегда пересчитываются»).

`npm run cursors -- sprite [--force]` - рендерит каждый курсор манифеста в `public/win-55-ui/cursors/<cursorId>/{normal,invert,native}.gif` (по одной директории на физический файл, не на схему/роль - дубликаты между схемами рендерятся один раз), nearest-neighbor. `normal.gif` / `invert.gif` - 2x масштаб (правило проекта для спрайтов), потребитель - `CursorOverlay` (`immersive`): `normal.gif` обычный alpha-слой (opaque там, где AND=0, либо где реальная альфа для `windows-default`), `invert.gif` - только инверт-пиксели, перекрашенные в сплошной белый, для наложения с `mix-blend-mode: difference` в рантайме. Слой без единого непрозрачного пикселя не пишется (у `crosshair`/`text` обычно нет `normal.gif`). `native.gif` - **1:1 масштаб**, потребитель - `native`-режим (голый CSS `cursor: url()`, blend недоступен): normal + invert слиты в один плоский битмап (`compositeNativeFrame`) снизу вверх - белая drop-shadow invert-пикселей со сдвигом 1px вправо-вниз, сами invert-пиксели сплошным чёрным, реальные пиксели normal-слоя сверху; печётся для каждого курсора. Для `.ani` учитываются `seq `/`rate` чанки (реальный порядок и тайминг кадров, не просто список хранимых кадров - шаги, повторяющие один и тот же кадр подряд, схлопываются в один GIF-кадр с суммарной задержкой). Существующий файл не перезаписывается без `--force` - спрайты предполагаются доступными для ручной подрисовки в редакторе, как `.bdf` у шрифтов; удалять устаревший файл, которого больше не должно быть (курсор сменил слой), тоже руками. `sprite` также публикует сами `manifest.json`/`scheme.json` в `public/win-55-ui/cursors/` - рантайм-реестр, который резолвит `CursorContext` (см. выше) - это всегда перезаписывается целиком, независимо от `--force`. Публикуемый `manifest.json` - не побайтовая копия `src-cursors/manifest.json`: к каждой записи добавляются `hasNormal`/`hasInvert`, проверенные прямо по факту существования файла в `public/win-55-ui/cursors/<cursorId>/` на момент публикации (а не пересчитанные из исходного `.cur`/`.ani` - так рукописная правка спрайта отражается в реестре как есть). Потребитель - `CursorOverlay`: не пытаться загрузить и словить 404, а знать заранее, какой слой реально есть. `native.gif` печётся для каждого курсора, так что `resolveCursorCss` берёт его без флага.

Для курсоров с `reconstructed && usesInvert` (`windows-default-crosshair`, `windows-default-text`) весь `normal`-слой целиком переносится в `invert` (перекрашенный в белый), а не рендерится плоским чёрным - реконструкция стирает AND/XOR-разметку, но оба этих курсора, как и их аналоги во всех остальных 18 наборах, являются «только инверт» дизайном без единого обычного непрозрачного пикселя, так что деление однозначно. Для гипотетической будущей reconstructed-записи, смешивающей инверт с настоящей заливкой, это правило было бы неверным - среди текущих 193 курсоров такой нет.

Байт-идентичные дубликаты между схемами (было 228 файлов на 193 уникальных курсора) схлопнуты в один физический файл при плоском переносе `src-cursors/` - имя `cursorId` достаётся самой широкой/общей категории среди дублирующих схем, а не выбирается по алфавиту: для большинства групп схемы - равноправные самостоятельные наборы без иерархии (например `3d-bronze` и `3d-white` совпадают в `crosshair`, но остаются каждый своей категорией - тут алфавитный порядок и решает), но у пары наборов такая иерархия есть. `hands-1`/`hands-2` - варианты одного семейства «hands»: курсор, совпадающий сразу в обоих, получает безномерное имя `hands-<role>` (например `hands-crosshair`, т.к. этот файл общий и для `hands-1`, и для `hands-2`, и для `conductor`/`old-fashioned` вдобавок), а курсор, совпадающий только с одним из них, получает имя этого конкретного варианта (`hands-1-nwse-resize` - общий с `conductor`, но не с `hands-2`). `windows-standard` (базовая, нерекрашенная схема) считается шире `windows-black` (её цветовой вариант) - три `xlarge`-курсора, общих у обеих, получили имя `windows-standard-xlarge-*`.

Регистрация спрайтов в рантайме UI-кита начата: `CursorContext` (см. «Компоненты» выше) резолвит `scheme`+`role` через опубликованные `manifest.json`/`scheme.json`. Пока это простой fetch+кэш в духе emoji-хелперов, а не скомпилированный register, как `generatedFonts.ts` у шрифтов - render-слой (invert/`mix-blend-mode`, анимация) ещё не реализован, только плоский `normal.gif`.

### TypeScript

Strict mode включён. ESLint запрещает unused locals/parameters, fallthrough switch cases.

## Workflow

Claude does not run/observe the dev server or take screenshots to verify UI changes — the user does that themselves (visual observation, feedback, iteration is their job, not Claude's). After making a change, it's enough to type-check (`vue-tsc -b`) and lint; add demo entries to `App.vue`'s kitchen sink so the user can look at the change, then stop and let them look.
